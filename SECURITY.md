# Security model

OpenBridge grants a paired computer (Mac or Windows PC) read, upload, rename and delete access to **one approved SAF tree**, or, if the user chooses **Whole phone** and grants Android's *All files access*, to all of shared storage (internal storage and SD cards, excluding `Android/data` and `Android/obb`), while sharing is on (in the app, or in the background with an ongoing notification if the user allows it). A paired computer can also read and set the phone's clipboard text while sharing. **Pairing is remembered**: a paired computer can reconnect without a code whenever the phone is sharing, until you tap **Forget** under *Trusted computers* on the phone. Pair only with computers you trust, on a trusted local network. There is no identity/account service.

- The Android listener binds only to a specific RFC1918 IPv4 address: either on a USB tethering interface (`rndis*`, `usb*`, `ncm*`, preferred when present, and reachable only by the cable-connected computer), or on an Android `TRANSPORT_WIFI` network with `NOT_VPN`. Unplugging the cable or turning tethering off stops sharing within about two seconds. It never binds wildcard, public, cellular, or IPv6 addresses. The peer address must also be RFC1918. It prefers port 41987 so saved computers find it again, and performs no UPnP, NAT traversal or port forwarding. While sharing over Wi‑Fi it announces itself on the local network with DNS-SD (`_openbridge._tcp`: the device name, address and port, which the phone otherwise shows on screen, and a short ID made of the first 8 bytes of its certificate fingerprint), so computers can list it and recognize a phone they saved; the announcement stops with sharing and grants nothing without pairing. The Mac accepts only literal RFC1918 endpoints, with no DNS or redirects. No software can prevent an administrator from deliberately forwarding or proxying a local port: do not expose it that way.
- All commands and file contents use TLS 1.2 or later. Android creates one RSA-2048 AndroidKeyStore key and self-signed certificate (valid for 25 years) the first time it shares, and keeps it while the app is installed; the private key never leaves the AndroidKeyStore. Reinstalling the app makes a new one, and saved computers then must pair again. After pairing, the Mac pins the SHA-256 digest of the exact leaf certificate DER and checks it on every connection **before sending credentials**. Public CA trust/hostname validation is replaced by this pin, not disabled without a replacement.
- **Pairing (OBP1/OBP2) is numeric comparison, as in Bluetooth.** The Mac connects without a pin and records the certificate it sees. The phone first sends a commitment (SHA-256 over its certificate fingerprint and a random nonce), then receives the Mac's random nonce, then reveals its own. The Mac checks the commitment against the certificate it saw, and both sides show a 6-digit code derived from the fingerprint and both nonces. A man in the middle presents a different certificate to each side and must fix its nonces before seeing the other side's, so the two codes match with probability about 1 in 10^6 per attempt; the user cancels on a mismatch. With OBP2 the computer also sends its name, which the phone shows when asking; a name proves nothing, so compare the codes. Only after the user taps **Pair** on the phone does it send the computer's secret; the Mac then pins the certificate. The phone handles one pairing request at a time and cancels it after a minute. Pairing depends on the user actually comparing the codes.
- Each paired computer gets its own cryptographically random 256-bit secret, required on every connection. The phone stores only its SHA-256 (with the computer's name and when it was last used) in app-private storage excluded from backups, and checks every record with `MessageDigest.isEqual`, so the list can't be used to connect as a computer. Secrets are sent only to a computer the user approved during pairing, and never shown, put in URLs, analytics, logs, or a cloud service. **Forget** on the phone revokes one computer at once; pairing again from the same computer replaces its old secret.
- The computer saves the phone's certificate fingerprint, its secret and last address so it can reconnect: on the Mac in `~/Library/Application Support/OpenBridge/phones.json` (mode 0600, excluded from Time Machine; not the Keychain, which would ask for the password after every update of an ad-hoc signed app), on Windows in `%APPDATA%\OpenBridge\phones.dat`, encrypted with DPAPI for the Windows account. Anyone who can read that file as you could connect to the phone while it shares, as with the screen mirroring key. Forget the phone in the app, or on the phone, to revoke it. A phone that no longer accepts the secret (forgotten, or reinstalled) is removed from the computer's list.
- The built-in Android external-storage document provider is the only supported authority. Android's picker grants a tree capability; no all-files/storage permission is requested. The server returns session-local opaque document IDs produced from that tree's enumeration. Client strings are never passed to filesystem paths or interpreted as document URIs. Unknown IDs, slash/backslash filenames, dot segments, controls, malformed UTF-8, oversized fields, negative/oversized file lengths, and unsupported operations are rejected.
- **Whole-phone mode** reads the filesystem directly. It lists only regular files and folders and never follows symbolic links, and every item is checked to lie inside a storage root before it is opened. Uploads are written to a temporary sibling and published with a move that fails if the name exists, so an existing file is never replaced. All files access stays granted in Android settings until the user revokes it; it is only used while sharing is on.
- Uploads reserve destination names within the process, reject existing names (ignoring case) and names the provider would rewrite, stream into a new temporary document, close the stream, recheck the destination, then rename and verify the resulting name. A failed transfer is deleted on cleanup. SAF does **not** offer a general atomic exclusive rename contract across external writers. Avoid modifying the shared folder with another app during transfers. Unexpected provider behavior or a simultaneous external rename remains a device-verification concern; the built-in provider must preserve the collision contract before release.
- Mac downloads use mode-0600 sibling temporary files (`.<name>.<size>.openbridge-part`) and a move which rejects an existing destination. An interrupted download keeps its partial file so the next download to the same place can continue it; the size in the name must match the phone's file, and a cancelled download deletes it. Neither side loads whole files into memory. Downloads are bounded to the declared size; a source file edited during a transfer, or between an interrupted transfer and its resume, can produce a mixed copy, so verify important files.
- **Clipboard.** CLIPBOARD GET and SET need the pairing secret like file access. Android lets OpenBridge read the clipboard only while its screen is in front; setting it works at any time and Android 13+ shows its own notice. Text is never logged or stored.
- Four concurrent Android handlers with a queue of eight (further connections are closed), a small accept backlog, 30-second socket read timeouts, bounded request fields/listings, and a bounded document-ID cache limit resource consumption. The Mac has a 30-second timeout per network read/write/handshake. These are safeguards for trusted-LAN use, not a promise of denial-of-service resistance on hostile networks. Android blocking socket writes may wait until transport failure or explicit stop if a peer stops reading.
- Stopping closes the listener and active sockets. Network loss or an address change stops sharing. **Background sharing** (on by default, with a switch on the main screen) keeps sharing after leaving the app through a foreground service with an ongoing "Sharing" notification and a Stop button, holding a partial wake lock and a Wi‑Fi lock while sharing; pairing requests then arrive as a notification with the code and Pair/Cancel. With background sharing off, leaving the app stops sharing as before. Android 15 limits background sharing to about six hours a day. While the app is on screen and sharing, the screen is kept on. Temporary files may survive an abrupt process kill; filenames clearly identify them. Storage access is deliberately not persisted across process restarts.

## USB File transfer (MTP)

The Mac app's USB File transfer connection does not use the protocol above. It talks to Android's built-in File transfer (MTP) mode directly, so none of the guarantees above apply to it:

- **No TLS and no pairing secret.** The trust boundary is the USB cable plus the user unlocking the phone and choosing File transfer. Data crosses the cable unencrypted, as with any MTP client, including Windows.
- **No single-folder restriction.** The Mac can see, download and upload anything Android exposes in File transfer mode, typically all shared internal storage and SD cards. OpenBridge never replaces files, and deletes only what you delete in the browser (after confirming) and its own partial upload after a failure.
- **Device identity.** A connection is bound to the phone it was opened on (manufacturer, model and serial number reported over MTP). After a USB error the Mac only reconnects to that same phone, and it only deletes a failed upload after re-reading the object and confirming its name, storage and folder still match.
- **macOS photo import.** If macOS's background photo import service (`ptpcamerad`) holds the phone, OpenBridge stops it once so it can open the device; macOS restarts it on demand.

Choose File transfer only on a Mac you trust, and switch the phone back to *No data transfer* afterwards. This mode is **beta** until verified on physical phones.

## Screen mirroring (USB debugging)

**Mirror screen** on the Mac uses Android's USB debugging (ADB), which is far more powerful than file access: a computer the phone trusts for USB debugging can run commands, install apps and read app data. OpenBridge uses it only to run the scrcpy server, but the trust itself is broad. Therefore:

- It works only over the cable and only after the phone's owner has turned on Developer options and USB debugging, and tapped **Allow** on the phone's prompt, which shows this Mac's key fingerprint.
- The Mac's key is a 2048-bit RSA key created on first use and stored at `~/Library/Application Support/OpenBridge/adbkey.der` (mode 0600). Anyone who can read that file and plug in the phone could use USB debugging as this Mac. Revoke it anytime in the phone's Developer options (**Revoke USB debugging authorizations**); turn USB debugging off when you don't need mirroring.
- OpenBridge pushes the official scrcpy 5.0.1 server (Apache-2.0, unmodified) to `/data/local/tmp/scrcpy-server.jar` and starts it with video only, no audio. The server file is downloaded when the app is built and verified against a pinned SHA-256 (see `third_party/scrcpy`). Mirroring sends the screen over the cable unencrypted, like scrcpy and ADB.
- While mirroring, text copied on either side is synced to the other (scrcpy's clipboard sync). Close the window to stop; the server exits when its connection closes.

## Deleting and renaming

A paired computer can delete and rename files and folders in what the phone shares, over Wi‑Fi or (on the Mac) USB File transfer. Both computer apps ask before deleting, name what will go, and warn that the phone has no bin: a folder is deleted with everything in it, and it can't be undone. The shared storage itself (or the shared folder in One folder mode) can't be deleted or renamed. Renaming never takes an existing name.

## Update check

Each app asks GitHub once per launch for the latest OpenBridge release (`api.github.com/repos/PredatorWoah/OpenBridge/releases/latest`) and shows a link when there's a newer one. It's an anonymous request that sends no information about you or your files; GitHub sees your IP address, as with any website. Nothing is downloaded or installed automatically, and a failure is silent.

## Windows app

The Windows app is a client like the Mac app and keeps the same rules for Wi‑Fi: it accepts only literal RFC1918 IPv4 addresses, pairs with OBP2 numeric comparison, pins the phone's certificate before sending the secret, and saves phones as described above. Downloads use the same `.<name>.<size>.openbridge-part` files and never replace an existing file. Phones are listed with DNS-SD (multicast DNS on the local network).

- **USB** on Windows is handled by Windows itself: OpenBridge only checks whether a portable device is present and opens File Explorer. The MTP notes above apply to Windows' own File transfer too.
- **Screen mirroring** runs the bundled official scrcpy for Windows (with its own `adb.exe`), pinned by SHA-256 (see `third_party/scrcpy`). The same USB debugging warnings apply. Its adb key lives in `%USERPROFILE%\.android\adbkey`, managed by adb, and adb may leave a small background server running on `127.0.0.1:5037` until you sign out or end it.
- The app is not code-signed yet, so Windows SmartScreen may warn the first time. Check the zip against `SHA256SUMS.txt` from the release.

## Verifying downloads

From 1.0.0, every Android APK is signed with the OpenBridge release key, whose certificate SHA-256 fingerprint is:

```
4E:41:B5:C8:0D:00:E4:0B:26:4A:BF:E6:5C:98:6A:8B:6D:1F:4F:DF:F7:E6:D1:7E:EB:66:10:5A:E4:BB:16:85
```

Check an APK with `apksigner verify --print-certs OpenBridge-<version>.apk` (Android SDK build tools). Do not install an APK signed with a different key. Each release also lists its files' SHA-256 checksums in `SHA256SUMS.txt`.

No real-device test, penetration test, or third-party security audit is claimed. Validate the [device checklist](docs/verification.md) before relying on the app for sensitive data.

Please avoid posting credentials or sensitive files in public bug reports. Report a vulnerability privately to the repository owner through GitHub's private vulnerability reporting if enabled, or request a private contact without posting exploit details.
